2
🔴 문제
1:55
지금 개발 현장에서는 무슨 일이 벌어지고 있을까요?

개발자 84%가 AI 코딩 도구를 씁니다. Google CEO가 밝힌 바로는 코드의 42%가 이미 AI가 작성하고 있습니다 — 이것도 이미 1년 반 전 얘기입니다.

지금 AI가 하루에 만들어내는 코드가 10억 줄이 넘습니다. 리눅스 운영체제 전체가 약 2,800만 줄인데요. AI가 하루에 리눅스 35개 분량의 코드를 만들어내는 겁니다.

그러면 우리가 이 코드들, 새로 생성된 프로젝트들을 이해할 수 있을까요?

코드를 이해할 수 있냐는 물음이 아닙니다. 이 프로젝트가 어떤 기능을 제공하는지, 사용자가 어떻게 써야 하는지, 비즈니스 규칙은 뭔지. 그걸 파악할 수 있느냐는 겁니다.

프롬프트 한 줄이면 앱과 웹이 만들어지는 세상입니다. AI가 스스로 판단해서 수십 초 만에 프로젝트를 만들어냅니다. 그런데 우리는 — 그걸 직접 실행시켜보고 나서야 이 프로젝트가 뭘 하는 건지 알게 됩니다. AI의 속도가 인간의 이해 속도를 이미 까마득하게 넘어선 겁니다.

결국 누군가는 이 프로젝트를 문서로 정리해야 합니다. 저같은 외주 개발자는 클라이언트에게 산출물을 납품해야 하고, 조직 내 개발팀은 기획자, 디자이너와 문서를 기반으로 일합니다. 코드만 있으면 되는 세상이 아닙니다.

그런데 AI가 코드를 바꾸는 속도를, 사람이 문서로 따라가는 건 물리적으로 불가능합니다. 코드는 하루에도 수십 번 바뀌는데, 문서는 아무도 안 고칩니다. 안 고치는 게 아니라 못 고치는 거죠.

그래서 Doklo를 만들었습니다.
84%, 42%로 시작 → 10억 줄/리눅스 35개로 스케일 체감 → "기능과 사용법" 전환 → 문서화 필요성 → "못 고치는 거죠"로 닫기.
3
💡 Why Doklo ★
1:35
그래서 Doklo를 만들었습니다. 이 테이블이 핵심입니다.

LLM에 직접 물어보면 — 결과가 텍스트로 나오고, 대화 끝나면 사라집니다. 매번 다른 답을 주고, 일일이 수동으로 물어봐야 합니다. 코드가 바뀌어도 모릅니다.

Doklo는 다릅니다. 코드를 분석해서 "Dok"이라는 구조화된 데이터로 저장합니다. Dok은 단순 텍스트가 아니라 비즈니스 로직이 구조화된 JSON입니다. 기능 단위, 비즈니스 규칙까지 전부 담겨 있습니다.

이 구조화된 데이터가 있기 때문에 — 프로덕트 원페이저, 기능 명세서, 사용자 플로우 같은 6종 문서가 0.01초 만에 자동 생성됩니다. Dok 하나가 바뀌면 연결된 모든 문서가 따라갑니다. 개발자가 코드를 커밋하면, PM이 보는 기획서가 자동으로 업데이트되는 겁니다.

기존 도구들은 파일 단위로 주석을 다는 수준입니다. Doklo는 "이 함수가 비즈니스에서 무슨 역할을 하는지"를 이해합니다. 관점이 다릅니다.

한마디로, Git이 코드의 변경 이력을 추적하듯, Doklo는 코드의 비즈니스 의미를 추적합니다.
테이블을 손가락으로 짚으며 설명. "커밋 → PM 기획서 자동 업데이트" 시나리오로 체감. Git 비유로 마무리.
4
⚙️ 제품 아키텍처
1:10
동작 과정을 보시겠습니다.

도클로는 요즘 유명한 오픈소스들과 마찬가지로 CLI로 제공이 됩니다. 프로젝트 폴더에서 "npx doklo init"이라고 입력만 하면 Doklo가 프로젝트 내 코드를 자동으로 읽어서 — 어떤 기능이 있는지, 각 기능이 어떻게 연결되는지 분석합니다.

그 결과를 AI가 비즈니스 기능 단위로 정리해서, 가운데 있는 "Dok"이라는 구조화된 데이터로 만듭니다. 이게 중심 허브입니다.

그리고 이 Dok 하나에서 — 제품 소개서, 기능 명세서, 사용자 플로우, 사용자 매뉴얼 같은 문서들이 자동으로 생성됩니다. 허브가 바뀌면, 연결된 모든 문서가 자동으로 따라갑니다.

실제로 프로젝트에 적용해서 결과를 확인한 상태입니다. 이론이 아니라 이미 동작하는 제품입니다.
다이어그램 왼쪽→가운데→오른쪽 순서로 가리키며 설명. "npx doklo init"으로 실제 제품 느낌. "이미 동작한다"로 마무리.
5
📈 시장
1:10
시장을 보겠습니다.

AI 코드 어시스턴트 시장이 2025년 8.1조에서 2030년 57.9조까지, 연평균 48% 성장합니다. AI가 코드를 더 많이 만들수록, 그 코드를 이해하는 도구의 수요도 같이 올라갑니다. 구조적으로 같이 갈 수밖에 없는 시장입니다.

그중 코드 문서화/이해 영역이 SAM 8.14조입니다.

타겟 고객은 명확합니다. 개발자 5~50명 규모의 SaaS 팀, 그리고 실제 서비스 런칭을 준비하는 1인 바이브코더입니다. 이 두 그룹이 코드 이해와 문서화 문제를 가장 심하게 겪으면서, 의사결정이 빠릅니다.

중요한 건 — 이 시장에서 "모던 코드 + 비즈니스 기능 단위"로 접근하는 플레이어가 없다는 겁니다.
동심원을 가리키며 TAM→SAM 순서로. 타겟 두 그룹(SaaS팀 + 바이브코더) 짚기. "비어있다" 강조. SOM은 장표에 보이니 굳이 읽지 않는다.
6
⚔️ 경쟁
1:05
경쟁사를 보면 오히려 저희 기회가 보입니다.

이 영역에 이미 1,670억원이 투자됐습니다. Swimm 500억, Mintlify 278억, 그리고 올해 2월 — 前 GitHub CEO가 퇴사해서 만든 Entire에 900억. 시장이 검증됐다는 뜻입니다.

그런데 Swimm은 500억 투자 받고도 레거시 코드로 피벗했습니다. 접근이 틀렸기 때문입니다. 파일 단위로 문서를 붙이는 건 — 코드가 바뀌면 문서가 깨집니다. 확장이 안 됩니다.

Mintlify는 API 문서 자동화 도구입니다. 비즈니스 로직은 건드리지 않습니다. Entire는 AI 에이전트를 관리하는 도구이지, 코드를 비즈니스 관점에서 이해시키는 도구가 아닙니다.

Doklo만이 "비즈니스 기능 단위"로 코드를 분석하고, 코드가 바뀌면 문서가 자동으로 따라갑니다. 이게 저희의 moat입니다.
"1,670억"으로 시장 검증. 각 경쟁사별 한계를 짚고, "moat" 선언으로 마무리.
7
🚀 Go-to-Market
1:00
전략은 심플합니다.
